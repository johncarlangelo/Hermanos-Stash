# UI/UX Enhancement Plan — Post-Overhaul Polish Round

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Push Hermanos Stash's UI/UX to launcher-grade quality (Raycast/PowerToys/Hermes-desktop tier) by adding the interaction patterns a *multi-tool* app needs: quick-switch navigation, richer tool discovery, polished toasts, and deeper personalization.

**Architecture:** All changes stay within the existing shell architecture — registry-driven tools, zustand stores, the typed `window.stash` bridge, and the shadcn/Radix component layer adopted in M7 + the deep-space glass design language from the ui-overhaul merge. No new process boundaries. Two small prefs additions (`ui.density`, per-tool pinning) reuse the existing prefs IPC.

**Tech Stack:** React 19 + TypeScript, Radix (via `radix-ui`), cmdk, zustand, Tailwind v4 tokens, vitest.

---

## Context / Current state

- 50 tools across 8 categories, registry-driven, all views share the fixed HERMANOS wordmark backdrop
- Shell: glass sidebar (favorites/recent/categories), Ctrl+K cmdk palette, drop-anywhere routing, dense mono status bar
- Existing shortcuts: `Ctrl+K` (palette), `Esc` (home), `Ctrl+1..5` (favorites)
- Toasts: custom `ToastViewport` (max 4, no stacking polish, no swipe)
- Tool pages: hero header + workspace; no way to see a tool's options without scrolling
- No recents *within* a session, no pinning beyond favorites, no density preference

---

## Feature set (decided)

### 1. Quick-Switch (`Ctrl+Tab`) — recent-tools cycling
Launcher-grade multi-tool navigation. Hold `Ctrl`, tap `Tab` to cycle through the last ~8 used tools in an overlay; release to jump. Like Alt-Tab but for tools.
- New `quickswitch` store slice reading `recents` (already persisted)
- Overlay component styled like the palette (glass card, tool icon + name rows)
- Keyboard-only interaction; `Shift+Tab` reverses direction
- Files: `features/shell/QuickSwitch.tsx` (new), `app/App.tsx` (global key handler), `stores/nav.ts` (slice)

### 2. Sonner-grade toast polish (replace custom ToastViewport)
Adopt `sonner` (the shadcn-standard toast lib), themed with our tokens.
- Glass cards, icon per kind, swipe-to-dismiss, pause-on-hover, stacked with depth
- Replace `stores/toasts.ts` internals; keep the exact `toastSuccess/toastError` API so 14 tool files don't change
- Files: `components/ui/Toaster.tsx` (new, wraps sonner `Toaster`), `stores/toasts.ts` (re-emit to sonner), `app/App.tsx` (mount)

### 3. Tool pinning + "Pinned" dock row in sidebar
Favorites exist; add *pinning* for a persistent top-of-sidebar dock independent of favorites ordering.
- Prefs `pinnedTools: string[]` (ordered), drag-to-reorder later (YAGNI now — up/down buttons)
- Sidebar gains a `PINNED` section between Workspace and Favorites
- Files: `stores/library.ts` (pin state), `features/shell/Sidebar.tsx`, `main/services/stores.ts` (prefs key)

### 4. Command palette upgrades: preview pane + action rows
Palette becomes a command center, not just search:
- Right-side preview card (glass) showing tool description, tags, favorite state, "last used 2h ago"
- Footer action hints: `Enter open · Ctrl+Enter open in background (records recent, stays) · ↑↓ navigate`
- `Ctrl+Enter` = open-in-background (pre-warms the lazy chunk, records recent)
- Files: `features/shell/CommandPalette.tsx`, `stores/nav.ts` (backgroundOpen action)

### 5. Density preference (Comfortable / Compact)
The one design-token-level preference users actually want in a utility app.
- Settings → Appearance: segmented control; `ui.density` pref (`comfortable | compact`)
- Compact: `html[data-density=compact]` scales base font 14→13px, row paddings −2px, card gaps −4px via CSS
- Files: `styles/global.css` (density block), `features/shell/SettingsView.tsx`, `accent-runtime.ts` (apply pre-paint like zoom/accent)

### 6. Empty-state storytelling
Home empty states currently generic. Add contextual guidance per state:
- No favorites yet → "Star a tool and it lands here. Try the palette: Ctrl K"
- No recents → "Tools you use appear here for one-click return"
- Category with 0 tools → honest "nothing here yet" + 3 suggested tools from nearest category
- Files: `features/shell/HomeView.tsx` (EmptyState variants), `components/ui/Feedback.tsx` (action slot already exists)

### 7. Micro-interaction pass (motion that reports state)
- Tool page options panels: Collapsible already exists — wrap advanced options (video/audio tools) so the workspace folds to essentials
- Result rows: stagger-in animation (30ms/row) on batch outputs
- DropZone: success pulse on accepted file (border flash ok-color, 400ms)
- Sidebar category rows: count badge ticks up/down with animation when tools register
- Files: `tools/shared/media-tool.tsx`, `components/ui/DropZone.tsx`, `features/shell/Sidebar.tsx`

### 8. Onboarding hint layer (first-run only)
One-time, dismissible coach marks — max 3, never again:
- "Ctrl K opens everything" (near search)
- "Drop any file on the window" (near workspace edge)
- "Pin tools you use daily" (near sidebar top)
- Prefs `onboarding.done: boolean`; skip entirely if set
- Files: `features/shell/OnboardingHints.tsx` (new), `app/App.tsx`

## Out of scope (recorded, not built)

- Global hotkey to summon the window (needs main-process work + Windows registration — separate milestone)
- Drag-to-reorder pinned tools (needs dnd-kit; up/down buttons suffice for v1)
- Themes beyond accent (dark-only stays per product constraint)
- Per-tool layout customization (YAGNI)

## Implementation order (dependency-aware)

1. **Toasts (F2)** — standalone, immediate polish, unblocks nothing but improves every flow
2. **Quick-Switch (F1)** — navigation core, uses existing recents
3. **Pinning (F3)** — store work, sidebar surface
4. **Palette upgrades (F4)** — builds on pinning/recents data
5. **Density (F5)** — token-level, touches settings
6. **Empty states (F6)** — pure UI
7. **Micro-interactions (F7)** — pure UI
8. **Onboarding (F8)** — last, references all the above features

Each feature = its own commit series on a fresh branch (`ux-polish`), conventional commits, merged after review.

## Verification per feature

- `npm run typecheck` → 0 errors
- `npm run test` → 568+ passing (new logic gets vitest suites: quickswitch cycling, pin ordering, density pref round-trip)
- `npm run build` → green
- Manual: keyboard-only walkthrough (Ctrl+K → Ctrl+Tab → pin → density toggle) with focus-visible checks
- Reduced-motion: all new animations must collapse under the existing `prefers-reduced-motion` block

## Risks / tradeoffs

- **Sonner swap** touches the toast API surface — mitigated by keeping `toastSuccess/toastError` signatures identical; 14 files untouched
- **Quick-Switch Ctrl+Tab** may conflict with OS/WebView defaults — Electron captures it fine, but verify on Windows; fallback `Ctrl+Q` if blocked
- **Density scaling** could break pixel-tuned overlays (titlebar height) — density only scales renderer content, never the `env(titlebar-area-*)` chrome
- **Onboarding hints** risk nagging — hard cap 3, one-time pref, never re-show
